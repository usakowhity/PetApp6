# 🐇 PetApp6 v1.3.1 -- 癒しウサギの日記帳

PetApp6 は、PetApp5 v3.2.7
の機能・ファイル構成・世界観を継承し、その上に日記帳機能を追加したアプリです。

PetApp5 の Direct Talk、音声認識、Diary → Emotion／Need → Rabbit
Action、Idle Layer
を土台として、日記の保存・一覧・詳細表示・編集・削除、サムネール付き日記帳の印刷／PDF保存に対応しています。

v1.2.1 で導入した **Rabbit Action の通常表示用メディアと、日記・印刷用の静止画を分離する設計**を継承しています。v1.2.2 では、日記の印刷／PDF保存ボタンと印刷用表示の実装を調整し、PDF表示が適切に行えることを確認しました。v1.3.0 では、Direct Talk に R22「散歩（おそと）」と R23「おめでとう（ハッピーバースデー）」を追加し、Rabbit Action を R01〜R23 に拡張しました。

**v1.3.1 はバグ修正版です。** 日記の感情判定で、「うれしい」「良かった」などの表記ゆれが喜び（joy）として認識されず、ウサギの反応が変わってしまう問題を修正しました。

## 🟩 1. 概要

PetApp6 は、PetApp5
を作り替えるのではなく、**既存の機能・モジュール・画像資産を活用しながら新しい機能を追加するアプリ**です。

### 主な機能

-   ユーザーが自由に設定できるペット名
-   Direct Talk（設定したペット名で話しかける機能）
-   SpeechRecognition による音声認識
-   日記の保存・一覧・詳細表示
-   日記に対応するウサギのアクション表示
-   日記本文の編集・削除
-   サムネール付き日記帳の印刷／PDF保存
-   Rabbit Action R01〜R23
-   MP4を使用するRabbit Actionの動画表示
-   日記一覧・日記詳細での印刷用代表画像表示
-   時間帯に応じた Idle Layer

## 🎙️ 3. Direct Talk の使い方

Direct Talk
は、ユーザーが設定したペット名を呼びかけの先頭につけて、ウサギに話しかける機能です。

例えば、ペット名が「レオ」の場合：

-   「レオ、おはよう」
-   「レオ、元気？」
-   「レオ、かわいい」
-   「レオ、おやすみ」
-   「レオ、ごはん」
-   「レオ、お水」
-   「レオ、トイレ」
-   「レオ、ハウス」
-   「レオ、散歩」
-   「レオ、おそと」
-   「レオ、おめでとう」
-   「レオ、ハッピーバースデー」

ペット名を「うさこ」に設定した場合は、「うさこ、かわいい」「うさこ、ハウス」のように呼びかけます。

**ペット名は「レオ」に固定されていません。**
ユーザーが設定した名前を使って呼びかけることができます。

### Direct Talk 辞書

  話しかけ内容                                   アクションID   意味
  ---------------------------------------------- -------------- ------------------
  おはよう                                       R10            朝のあいさつ
  元気                                           R11            元気確認
  かわいい／可愛い／カワイイ／おりこう／お利口   R14            喜び反応
  おやすみ                                       R15            休息
  ねんね                                         R08            眠る反応
  おいで                                         R16            呼びかけへの反応
  ごはん                                         R19            食事行動
  牧草／チモシー                                 R17            食事行動（草）
  水／お水                                       R18            飲水行動
  お腹すいた                                     R03            空腹反応
  トイレ／おしっこ／ちっち／シーして／シー       R20            トイレの反応
  ハウス／おうち                                 R21            ハウスに入る反応
  散歩／おそと                                   R22            散歩・外に出る反応
  おめでとう／ハッピーバースデー                 R23            お祝い・誕生日反応

## 🟨 4. 日記帳機能

### 4.1 日記の保存

日記本文と日付などの情報を、ブラウザの `localStorage` に保存します。

### 4.2 日記一覧

保存済みの日記を新しい順に一覧表示します。

一覧には、

-   日付
-   本文の冒頭
-   対応するウサギのアクション
-   印刷用代表画像

を表示します。

### 4.3 日記詳細

日記詳細画面では、

-   日付
-   日記本文（改行を保持）
-   対応するウサギのアクション
-   印刷用代表画像
-   編集・追記
-   削除
-   一覧に戻る

を表示します。

### 4.4 日記の編集・追記

保存済みの日記本文や日付を編集して保存できます。

### 4.5 日記の削除

選択した日記を削除し、更新された一覧を表示します。削除時には確認メッセージを表示します。

### 4.6 サムネール付き日記帳の印刷／PDF保存

保存済みの日記を印刷用レイアウトにまとめて出力できます。

日記ごとに、

-   日付
-   本文
-   対応するウサギの印刷用代表画像
-   アクション名（定義されている場合）

を表示します。

ブラウザ標準の印刷機能を使用するため、PDF生成用の外部ライブラリは必要ありません。

印刷画面で「PDFとして保存」を選択するとPDFファイルとして保存でき、プリンターを選択すれば紙に印刷できます。

## 💗 5. 日記の感情判定（Emotion／Need）

日記を保存すると、本文のキーワードから Emotion（感情）と Need（求めていること）を判定し、対応する Rabbit Action を選びます。判定は LLM を使わない軽量なルールベース方式です。

### 喜び（joy）の判定

次の表現を含む日記は、すべて `joy`（Need は `share_joy`）と判定し、**R14「ぴょんっと喜ぶ」** になります。

  表現                          例
  ----------------------------- ----------------------------------
  嬉／うれし                    嬉しい、うれしい、うれしかった
  楽し                          楽しい、楽しかった
  良かった／よかった            良かった、よかったな
  ご機嫌                        ご機嫌
  ラッキー                      ラッキー

判定に使う正規表現：

``` js
/嬉|うれし|楽し|良かった|よかった|ご機嫌|ラッキー/
```

漢字・ひらがなの表記が違っても、同じ反応になります。

どの感情にも当てはまらない日記は、既定の `pleasant`（Need は `companionship`）として扱い、R04「じっと隣で見守る」になります。

### 判定のしくみ

``` text
日記本文
   ↓ detectEmotionNeed()（app.js）
Emotion × Need
   ↓ action_mapping.json
Rabbit Action ID
   ↓ rabbitActionSelector.js
ウサギの反応を表示
```

感情語の追加や表記ゆれの調整は、`app.js` の `detectEmotionNeed()` の正規表現だけで行えます。`action_mapping.json` と `rabbitActionSelector.js` を変更する必要はありません。

## 🖼️ 6. Rabbit Action のメディア設計

v1.2.1 では、Rabbit Action のメディアを2種類に明確に分離します。

### `image`

**実際のウサギ反応表示用メディア**です。

Direct Talk、Diary Reaction、Idle Layer などで使用します。

PNGだけでなくMP4も使用できます。

### `print_image`

**日記・記録・印刷用の代表静止画**です。

日記一覧のサムネール、日記詳細、日記帳の印刷／PDF保存では、この
`print_image` を使用します。

このため、MP4を使用するRabbit
Actionでも、印刷時に動画を画像として扱おうとする問題を避けられます。

### 基本ルール

``` text
Rabbit Action
      │
      ├─ image
      │    └─ 通常表示用
      │       PNG / MP4
      │
      └─ print_image
           └─ 日記・印刷用代表画像
              PNG
```

MP4を持つRabbit Actionには、対応するPNGを必ず用意して `print_image`
に登録します。

### 例：R08

``` json
{
  "id": "R08",
  "name": "ごろんと安心する",
  "image": "assets/rabbit/actions/R08.mp4",
  "print_image": "assets/rabbit/actions/R08.png"
}
```

これにより、

``` text
Direct Talk / Diary Reaction
        ↓
     R08.mp4

日記一覧
日記詳細
印刷／PDF
        ↓
     R08.png
```

となります。

### MP4を使用するアクション

v1.2.1では、MP4を使用するアクションについて、対応するPNGを印刷用代表画像として登録する設計です。

-   R08 → R08.mp4 / R08.png
-   R17 → R17.mp4 / R17.png
-   R18 → R18.mp4 / R18.png
-   R19 → R19.mp4 / R19.png

今後新しいMP4アクションを追加する場合も、同じ規則を使用します。

## ✏️ 8. 日記帳の使い方

### ① 日記を書く

画面の「今日の日記」カードにあるテキストエリアに、日々の出来事や気持ちを書きます。

例：

``` text
今日ちょっと疲れたけど、ウサギに癒された。
```

### ② 「ウサギに聞かせる」ボタンを押す

入力した文章を日記として保存し、ウサギの反応を表示する処理を実行します。

日記データにはID、日付、本文などを保存します。日記に対応するアクションが選択された場合は、`actionId`
にそのアクションIDを保存します。

### ③ 日記一覧を見る

「日記帳」カードに保存済みの日記が新しい順に表示されます。

### ④ 日記詳細を見る

一覧から日記を選ぶと詳細画面に切り替わります。

### ⑤ 日記を編集・追記する

詳細画面の編集機能から本文や日付を修正して保存します。

編集しても、保存済みの `actionId`（ウサギの反応）は変わりません。

### ⑥ 日記を削除する

詳細画面の「削除」ボタンから選択した日記を削除できます。

## 🖨️ 9. 日記帳を印刷／PDF保存する方法

1.  日記を入力して「ウサギに聞かせる」ボタンを押し、日記帳に保存します。
2.  日記帳画面の「🖨️ 印刷／PDF保存」ボタンを押します。
3.  ブラウザの印刷ダイアログで「PDFとして保存」またはプリンターを選びます。

印刷用日記帳では、MP4ではなく `print_image`
に登録されたPNGを使用します。

そのため、R08など動画を使用するアクションでも、PDFには静止画として適切に掲載できます。

### v1.2.2 の印刷／PDF表示の修正

- 日記の印刷／PDF保存ボタンを画面上で表示しやすいように調整
- `index.html` に印刷操作領域の識別用 `diary-export-actions` を追加
- `style.css` で印刷ボタンの表示・配置を明示
- `app.js` で日記一覧・詳細・印刷／PDFに印刷用代表画像（`print_image`）を使用する処理を整理
- 画面表示用の印刷専用領域は通常画面では非表示とし、印刷時に表示する設計を維持

実際にPDF表示がきれいに行えることを確認しました。

## 💾 10. 日記データの保存場所

日記はブラウザの `localStorage` に保存します。

保存キー：

``` text
petapp6_diaries
```

日記データの基本形式：

``` json
{
  "id": "2026-10-12T09:15:23.123Z",
  "date": "2026-10-12",
  "text": "今日は少し疲れたけど、ウサギに癒された。",
  "emotion": null,
  "need": null,
  "actionId": "R08"
}
```

-   `id`：日記を識別するID
-   `date`：日付（`YYYY-MM-DD`）
-   `text`：日記本文
-   `emotion`／`need`：互換性維持用
-   `actionId`：日記に対応するRabbit Action ID

重要なのは、**日記データには画像ファイル名ではなく `actionId`
を保存する**ことです。

したがって、R08の通常表示をPNGからMP4に変更しても、既存の日記データを書き換える必要はありません。

v1.3.1 の感情判定の修正は、これから保存する日記に適用されます。保存済みの日記の `actionId` は書き換えません。

## 🔍 11. 保存された日記を確認する方法

### Chrome／Microsoft Edge の場合

1.  PetApp6を開きます。
2.  `F12` キーを押して開発者ツールを開きます。
3.  「Application」（日本語UIでは「アプリケーション」）を選択します。
4.  「Storage」→「Local Storage」を開きます。
5.  PetApp6を開いているオリジンを選択します。
6.  キー一覧から `petapp6_diaries` を探します。
7.  値を確認すると、保存されている日記データを確認できます。

## 🐇 13. 開発方針

> **既存機能を削らず、既存モジュールと資産を温存しながら、新しい層を追加する。**

PetApp6は差分追加型で開発します。

-   PetApp5の既存機能を不用意に削除しない
-   既存のJavaScriptモジュールや画像資産を活用する
-   日記帳機能は独立したモジュールに分けて管理する
-   Direct Talkの追加アクションは既存の仕組みを活用する
-   既存機能と追加機能の共存を重視する
-   将来の拡張に必要な基盤を維持する
-   メディアの用途が異なる場合は、役割を明示的に分離する

**機能を使わないことはあっても、将来必要な基盤を削らない。**
