PetApp6 は、PetApp5 v3.2.7
の機能・ファイル構成・世界観を継承し、その上に日記帳機能を追加したアプリです。

PetApp5 の Direct Talk、音声認識、Diary → Emotion／Need → Rabbit
Action、Idle Layer
を土台として、日記の保存・一覧・詳細表示・編集・削除、サムネール付き日記帳の印刷／PDF保存に対応しています。

v1.2.1 で導入した **Rabbit Action の通常表示用メディアと、日記・印刷用の静止画を分離する設計**を継承しています。v1.2.2 では、日記の印刷／PDF保存ボタンと印刷用表示の実装を調整し、PDF表示が適切に行えることを確認しました。v1.3.0 では、Direct Talk に R22「散歩（おそと）」と R23「おめでとう（ハッピーバースデー）」を追加し、Rabbit Action を R01〜R23 に拡張しました。v1.3.1 では、日記の感情判定で「うれしい」「良かった」などの表記ゆれが喜び（joy）として認識されず、ウサギの反応が変わってしまう問題を修正しました。

v1.3.2 では、README の整備、ホーム画面の画像、デモ動画へのリンク、日英 README の相互リンクを追加しました（アプリ本体の機能・挙動は変更していません）。

**v1.3.3 では、日記に対するウサギの反応を拡充し、Rabbit Action R01〜R23 のすべてが日記・Direct Talk・待機のいずれかから出るようになりました。** あわせて、動画（MP4）を使用する Rabbit Action（R08 など）が、日記一覧・日記詳細・印刷／PDF保存で静止画（PNG）として表示されるよう修正しました。

**v1.3.4 では、素材の利用条件を見直し、それまで使っていた動画（MP4）をすべてやめて、ウサギの表示を静止画（PNG）にしました。** あわせて、R08・R15・R19 に別画像（R08-1・R15-1・R19-1）を追加し、ランダムに表示するようにしました。

**v1.3.5 では、R17（牧草）・R18（水を飲む）・R19（ごはん）に、音入りの動画を追加しました。** 動画は朝夕の食事時の待機表示などで再生されます。音は初期状態ではオフで、動画の表示中に右下に出るボタン（🔇／🔊）で切り替えられます。動画を再生できない環境では、静止画（PNG）に自動で切り替わります。

**ウサギの一日のリズムを表現しました。** ウサギは、明け方と夕暮れに活発になる動物と言われます。v1.3.5 の待機表示は、それに合わせて、昼と夜は静かな静止画、朝と夕方の食事時は音入りの動画で、生き生きとした食事の様子を見せます。

| 時間帯 | ウサギの様子 |
|---|---|
| 朝（6〜10時） | 食事（音入りの動画：牧草・水・ごはん） |
| 昼（10〜16時） | 静かにくつろぐ（静止画） |
| 夕方（16〜20時） | 食事（音入りの動画：牧草・水・ごはん） |
| 夜（20〜6時） | 眠る（静止画） |

**v1.3.6 では、Direct Talk が言葉の表記ゆれに対応しました。** 音声認識は、同じ言葉を「ごはん」「ご飯」のように、ひらがなや漢字で返すことがあります。「レオ、ご飯」と話しかけても反応するようになりました。あわせて、PDF保存のときの初期ファイル名に日付を入れました（例：`癒しウサギの日記帳_2026-10-30`）。

ウサギの画像・動画は、すべて生成AIで作成したものです（画像は ChatGPT、R17・R18・R19 の動画は Google Flow（Veo 3.1 Lite））。コード（`js/`、`data/`、`css/`、`index.html`）は MIT ライセンスですが、画像・動画（`assets/` 配下）は MIT ライセンスの対象外です。再利用・再配布はご遠慮ください。

## 🟩 1. 概要

PetApp6 は、PetApp5
を作り替えるのではなく、**既存の機能・モジュール・画像資産を活用しながら新しい機能を追加するアプリ**です。

### 主な機能

-   ユーザーが自由に設定できるペット名
-   Direct Talk（設定したペット名で話しかける機能）
-   SpeechRecognition による音声認識
-   日記の保存・一覧・詳細表示
-   日記に対応するウサギのアクション表示
-   日記本文の編集・削除
-   サムネール付き日記帳の印刷／PDF保存
-   Rabbit Action R01〜R23
-   PNG画像のランダム表示（R08・R15・R19、待機表示）
-   音入り動画の再生（R17・R18・R19）と、右下の音のオン／オフボタン（初期はオフ）
-   日記一覧・日記詳細での印刷用代表画像表示
-   時間帯に応じた Idle Layer
-   感情ごとに複数の候補を持つ日記の反応（候補の中から均等にランダム選択）

## 🎙️ 3. Direct Talk の使い方

Direct Talk
は、ユーザーが設定したペット名を呼びかけの先頭につけて、ウサギに話しかける機能です。

例えば、ペット名が「レオ」の場合：

-   「レオ、おはよう」
-   「レオ、元気？」
-   「レオ、かわいい」
-   「レオ、おやすみ」
-   「レオ、ごはん」
-   「レオ、お水」
-   「レオ、トイレ」
-   「レオ、ハウス」
-   「レオ、散歩」
-   「レオ、おそと」
-   「レオ、おめでとう」
-   「レオ、ハッピーバースデー」

ペット名を「うさこ」に設定した場合は、「うさこ、かわいい」「うさこ、ハウス」のように呼びかけます。

**ペット名は「レオ」に固定されていません。**
ユーザーが設定した名前を使って呼びかけることができます。

Direct Talk は**音声専用**です。音声認識の言語は日本語（`ja-JP`）で、Chrome や Edge など音声認識に対応したブラウザで使えます。音声認識の結果が、設定したペット名で始まる場合だけ反応します（例：認識結果がカタカナなら、名前もカタカナにします）。

### Direct Talk 辞書

音声認識は、同じ言葉をひらがな・漢字・カタカナのどれで返すか一定しません。表にある書き方は、どれでも反応します（v1.3.6 で表記ゆれに対応）。

| 話しかけ内容 | アクションID | 意味 |
|---|---|---|
| おはよう／お早う | R10 | 朝のあいさつ |
| 元気 | R11 | 元気確認 |
| かわいい／可愛い／カワイイ／いいこ／いい子／良い子／おりこう／お利口 | R14 | 喜び反応 |
| おやすみ／お休み | R15 | 休息 |
| ねんね／ネンネ | R08 | 眠る反応 |
| おいで | R16 | 呼びかけへの反応 |
| ごはん／ご飯／ゴハン／御飯 | R19 | 食事行動 |
| 牧草／チモシー | R17 | 食事行動（草） |
| 水／お水 | R18 | 飲水行動 |
| お腹／おなか／すいた／空いた（お腹すいた など） | R03 | 空腹反応 |
| トイレ／おしっこ／ちっち／シーして／シー | R20 | トイレの反応 |
| ハウス／おうち／お家 | R21 | ハウスに入る反応 |
| 散歩／さんぽ／サンポ／おそと／お外 | R22 | 散歩・外に出る反応 |
| おめでとう／ハッピーバースデー／バースデー／誕生日 | R23 | お祝い・誕生日反応 |

## 🟨 4. 日記帳機能

### 4.1 日記の保存

日記本文と日付などの情報を、ブラウザの `localStorage` に保存します。

### 4.2 日記一覧

保存済みの日記を新しい順に一覧表示します。

一覧には、

-   日付
-   本文の冒頭
-   対応するウサギのアクション
-   印刷用代表画像

を表示します。

### 4.3 日記詳細

日記詳細画面では、

-   日付
-   日記本文（改行を保持）
-   対応するウサギのアクション
-   印刷用代表画像
-   編集・追記
-   削除
-   一覧に戻る

を表示します。

### 4.4 日記の編集・追記

保存済みの日記本文や日付を編集して保存できます。

### 4.5 日記の削除

選択した日記を削除し、更新された一覧を表示します。削除時には確認メッセージを表示します。

### 4.6 サムネール付き日記帳の印刷／PDF保存

保存済みの日記を印刷用レイアウトにまとめて出力できます。

日記ごとに、

-   日付
-   本文
-   対応するウサギの印刷用代表画像
-   アクション名（定義されている場合）

を表示します。

ブラウザ標準の印刷機能を使用するため、PDF生成用の外部ライブラリは必要ありません。

印刷画面で「PDFとして保存」を選択するとPDFファイルとして保存でき、プリンターを選択すれば紙に印刷できます。

PDFの初期ファイル名は、日付つきの `癒しウサギの日記帳_YYYY-MM-DD` になります（v1.3.6。ブラウザによっては反映されないことがあります）。

## 💗 5. 日記の感情判定（Emotion／Need）

日記を保存すると、本文のキーワードから Emotion（感情）と Need（求めていること）を判定し、対応する Rabbit Action を選びます。判定は LLM を使わない軽量なルールベース方式です。

### 日記の反応（v1.3.3 で拡充）

日記本文のキーワードから感情を判定し、次の Rabbit Action からランダムに1つ選びます。

| 日記のキーワード | 選ばれる Rabbit Action |
|---|---|
| 疲／しんど／きつ／だる／眠い／眠た | R15 / R05 / R08（各1/3） |
| 悲／つら／泣／涙／えーん／ガーン／ショック | R01 / R02 / R06 / R07（各1/4） |
| 不安／心配／怖／びくびく | R03 / R09 / R10 / R12（各1/4） |
| 寂／孤独／しゅん | R01 / R02 / R05 / R06 / R16（各1/5） |
| 嬉／うれし／楽し／良かった／よかった／いいね／ご機嫌／ラッキー | R14 |
| 怒／おこ／イラ／むか／プンプン | R11 / R12（各1/2） |
| 上記以外 | R04 / R13（各1/2） |

- 複数の感情語を含む日記は、上の表の上から順に（疲れ → 悲しみ → 不安 → 寂しさ → 喜び → 怒り）、最初に当てはまったものを採用します。
- 候補が複数ある場合は、すべての候補から均等に選びます。v1.3.3 でセレクタを修正しました（従来は先頭3件だけが対象で、4件目以降の候補は選ばれませんでした）。
- 保存済みの日記の反応（`actionId`）は書き換えません。

### 喜び（joy）の判定（v1.3.1 で修正）

次の表現を含む日記は、すべて `joy`（Need は `share_joy`）と判定し、**R14「ぴょんっと喜ぶ」** になります。

| 表現 | 例 |
|---|---|
| 嬉／うれし | 嬉しい、うれしい、うれしかった |
| 楽し | 楽しい、楽しかった |
| 良かった／よかった | 良かった、よかったな |
| いいね | いいね |
| ご機嫌 | ご機嫌 |
| ラッキー | ラッキー |

判定に使う正規表現：

``` js
/嬉|うれし|楽し|良かった|よかった|いいね|ご機嫌|ラッキー/
```

漢字・ひらがなの表記が違っても、同じ反応になります。

どの感情にも当てはまらない日記は、既定の `pleasant`（Need は `companionship`）として扱い、R04「じっと隣で見守る」または R13「そっと励ます（正面座り）」になります。

### 判定のしくみ

``` text
日記本文
   ↓ detectEmotionNeed()（app.js）
Emotion × Need
   ↓ action_mapping.json
Rabbit Action の候補
   ↓ rabbitActionSelector.js（候補から均等に選択）
ウサギの反応を表示
```

感情語の追加や表記ゆれの調整は、`app.js` の `detectEmotionNeed()` の正規表現だけで行えます。反応の候補を変えたいときは `data/action_mapping.json` を編集します。どちらの場合も `rabbitActionSelector.js` を変更する必要はありません。

## 🖼️ 6. Rabbit Action のメディア設計

Rabbit Action のメディアは、静止画（PNG）を基本とし、一部のアクションにだけ動画（MP4）を追加できる設計です。

### `image`

そのアクションの**代表画像（PNG）**です。通常のウサギ表示のほか、日記一覧のサムネール、日記詳細、印刷／PDF保存で使います。動画を再生できないときの代わりの表示にもなります。

### `video`（任意）

そのアクションの**動画（MP4）**です。`video` があるアクションは、ウサギの表示で動画を再生します。動画の再生に失敗したときは、`image`（PNG）を表示します。日記一覧・日記詳細・印刷／PDF保存では、動画は使わず、`image` を使います。

``` json
{
  "id": "R18",
  "image": "assets/rabbit/actions/R18.png",
  "video": "assets/rabbit/actions/R18.mp4"
}
```

### `variants`（任意）

同じアクションの**別バージョンの静止画**を登録する配列です。`variants` があるアクションは、表示のたびに `image` と `variants` の中から1枚をランダムに選びます。ただし、`video` があるアクションでは、動画の合間に静止画が出ると止まって見えるため、`variants` は使いません。

``` json
{
  "id": "R08",
  "image": "assets/rabbit/actions/R08.png",
  "variants": ["assets/rabbit/actions/R08-1.png"]
}
```

### アクションごとの表示

| アクション | 表示 |
|---|---|
| R17（牧草）・R18（水を飲む）・R19（ごはん） | 動画（R17.mp4 / R18.mp4 / R19.mp4）。再生できないときは PNG |
| R08 | R08.png / R08-1.png をランダム |
| R15 | R15.png / R15-1.png をランダム |
| 上記以外 | PNG |

R19-1.png は、R19 の動画を使わない場合に備えて残している別画像です。

### 待機表示（Idle Layer）

待機表示は20秒ごとに切り替わり、時間帯ごとに次の中から、**同じ確率**で選びます。

| 時間帯 | 表示 |
|---|---|
| 朝（6〜10時）・夕（16〜20時）：食事 | R17・R18・R19 の動画（各1/3） |
| 昼（10〜16時） | R08.png / R08-1.png |
| 夜（20〜6時） | R15.png / R15-1.png |

Direct Talk と日記の反応でも、R08・R15 が選ばれたときは、2枚のどちらかがランダムに表示されます。R17・R18・R19 は動画で表示されます。

### 動画の音

-   動画には音が入っています。**初期状態はオフ（ミュート）**です。
-   動画の表示中は、ウサギの表示の右下に小さなボタンが出ます。🔇 を押すと音が出て（🔊）、もう一度押すと消えます。
-   音のオン／オフの設定は、ブラウザに保存されます。
-   ブラウザの仕組みにより、画面を一度も操作していない状態では、音が出ないことがあります。
-   音を出した状態では、Direct Talk の音声認識が動画の音を拾うことがあります。気になる場合は、音をオフにしてください。

### 変更の経緯

-   v1.3.4：動画をすべてやめ、静止画（PNG）に統一。`print_image` を廃止し、`variants` を追加
-   v1.3.5：`video` を追加し、R17・R18・R19 に音入り動画を再導入。`image` は常に PNG とし、動画の失敗時の代わり、サムネール、印刷／PDF に使用

## ✏️ 8. 日記帳の使い方

### ① 日記を書く

画面の「今日の日記」カードにあるテキストエリアに、日々の出来事や気持ちを書きます。

例：

``` text
今日ちょっと疲れたけど、ウサギに癒された。
```

### ② 「ウサギに聞かせる」ボタンを押す

入力した文章を日記として保存し、ウサギの反応を表示する処理を実行します。

日記データにはID、日付、本文などを保存します。日記に対応するアクションが選択された場合は、`actionId`
にそのアクションIDを保存します。

### ③ 日記一覧を見る

## 🖨️ 9. 日記帳を印刷／PDF保存する方法

1.  日記を入力して「ウサギに聞かせる」ボタンを押し、日記帳に保存します。
2.  日記帳画面の「🖨️ 印刷／PDF保存」ボタンを押します。
3.  ブラウザの印刷ダイアログで「PDFとして保存」またはプリンターを選びます。

印刷用日記帳では、各アクションの代表画像（`image`、PNG）を使用します。

### PDF保存について

-   PDFには、**保存した時点の日記がすべて**入ります（古い日記から順）。
-   後日もう一度保存すると、新しい日記を含む**新しいPDF**ができます。前に保存したPDFは変わりません。
-   保存先とファイル名は、ブラウザの保存画面で決めます。同じ名前のファイルが同じ場所にあるときの扱い（上書き・別名）は、ブラウザやOSによって異なります。v1.3.6 から、初期のファイル名に日付が入ります。
-   別のサイトや別のブラウザで保存すると、日記の保存先が別なので、別の内容のPDFになります（「10. 日記データの保存場所」を参照）。

- `style.css` で印刷ボタンの表示・配置を明示
- `app.js` で日記一覧・詳細・印刷／PDFに代表画像を使用する処理を整理
- 画面表示用の印刷専用領域は通常画面では非表示とし、印刷時に表示する設計を維持

実際にPDF表示がきれいに行えることを確認しました。

## 💾 10. 日記データの保存場所

日記はブラウザの `localStorage` に保存します。

保存キー：

``` text
petapp6_diaries
```

日記データの基本形式：

``` json
{
  "id": "2026-10-12T09:15:23.123Z",
  "date": "2026-10-12",
  "text": "今日は少し疲れたけど、ウサギに癒された。",
  "emotion": null,
  "need": null,
  "actionId": "R08"
}
```

-   `id`：日記を識別するID
-   `date`：日付（`YYYY-MM-DD`）
-   `text`：日記本文
-   `emotion`／`need`：互換性維持用
-   `actionId`：日記に対応するRabbit Action ID

重要なのは、**日記データには画像ファイル名ではなく `actionId`
を保存する**ことです。

したがって、R08の表示画像を変更しても、既存の日記データを書き換える必要はありません。

v1.3.1 の感情判定の修正は、これから保存する日記に適用されます。保存済みの日記の `actionId` は書き換えません。

v1.3.3 での日記の反応候補の拡充も、これから保存する日記に適用されます。保存済みの日記の反応は変わりません。

### 日記の保存先について（重要）

日記は、**お使いのブラウザの中にだけ**保存されます。保存先は、次の組み合わせごとに別になります。

-   サイトのアドレス（GitHub Pages・Vercel・Netlify・VS Code の Live Server などは、すべて別）
-   ブラウザ（Chrome と Edge など）と、ブラウザのプロフィール
-   端末（PCとスマホなど）

そのため、サイトや端末を変えると、日記は引き継がれません。ブラウザの閲覧データを削除すると、日記も消えます（元に戻せません）。残したい日記は、**印刷／PDF保存**で保存してください。普段使うサイトを1つに決めておくと、日記が散らばりません。

日記本文と反応（`actionId`）はブラウザの `localStorage` にだけ保存され、アプリが外部サーバーへ送信することはありません（アプリのコードは、同じサイト内のファイル以外を読み込みません）。Direct Talk の音声認識にはブラウザ内蔵の機能を使います。ブラウザによっては、音声がブラウザの提供元のサーバーで処理されることがあります。

## 🐇 13. 開発方針

> **既存機能を削らず、既存モジュールと資産を温存しながら、新しい層を追加する。**

PetApp6は差分追加型で開発します。

-   PetApp5の既存機能を不用意に削除しない
-   既存のJavaScriptモジュールや画像資産を活用する
-   日記帳機能は独立したモジュールに分けて管理する
-   Direct Talkの追加アクションは既存の仕組みを活用する
-   既存機能と追加機能の共存を重視する
-   将来の拡張に必要な基盤を維持する
-   メディアの用途が異なる場合は、役割を明示的に分離する

**機能を使わないことはあっても、将来必要な基盤を削らない。**
